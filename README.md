# 番组口袋 · Bangumi Pocket

为手机重新设计的 Bangumi 非官方 Android 客户端。前端使用 React、TypeScript 和 Vite，Android 使用 Capacitor 8 封装，界面随 APK 一起打包。不是直接嵌入 bgm.tv 网页。

各版本新增功能与 bug 修复见 [版本变更日志](CHANGELOG.md)。后续修改同步维护日志，未发布改动先记入「未发布」，打包后归入对应版本。

源码仓库：[Wepdekr/bangumi-pocket](https://github.com/Wepdekr/bangumi-pocket)。

## 下载 Android 安装包

[下载最新版 APK](https://github.com/Wepdekr/bangumi-pocket/releases/latest) · [全部历史版本](https://github.com/Wepdekr/bangumi-pocket/releases)

打开 Release 页面，在 **Assets** 中选择 `bangumi-pocket-版本号.apk` 下载，安装到手机即可。`Source code` 是源码压缩包。APK 最低支持 Android 7.0，当前使用与此前安装包一致的开发调试签名；同一签名的新版可以覆盖安装。

```sh
git clone https://github.com/Wepdekr/bangumi-pocket.git
cd bangumi-pocket
npm ci
npm run dev
```

## 功能（v0.9.2）

收藏页默认显示「在看」，方便继续观看；列表直接显示实际收藏状态，去掉重复的收藏提示。

章节页仅通过右侧勾选按钮合并显示观看和放送状态，不增加上方汇总框；原有集数样式保持不变，右侧粉色空心勾选按钮表示章节已放送未看，灰色空心表示未放送或日期待定，粉色实心表示已看。已完结作品的未看章节使用粉色空心。此标记适用于动画、电视剧等有有效章节日期的作品。角色网格统一顶部对齐，完整声优名单自然换行，避免长名单导致相邻头像错位。

收藏页的「应用更新」读取最新 Release 的 update.json 附件，不依赖 GitHub REST API 的匿名 IP 限额，可手动检查最新正式版。有新版时弹窗显示版本号、安装包大小与更新说明，可滚动阅读、下载更新或暂不更新；关闭后可再次查看。下载后打开 APK，按 Android 提示安装；使用相同签名覆盖升级可保留账号和收藏。检查不需要登录，网络异常时可直接查看 GitHub 版本页面。

角色图片区采用圆角方形，图片从顶部居中裁切，避免全身立绘默认居中裁切后只显示躯干。

统一纯文本显示层：解码完整 HTML 命名实体及十进制 / 十六进制数字实体，覆盖发现、放送、搜索、收藏、作品详情、章节、角色、账号昵称、短评 / 长评、动态与互动者名字。只在显示时解码一次，不递归解码，不解析 HTML 标签，不修改接口原始数据、旧缓存、URL、账号标识或待提交的评价输入。旧放送接口返回 `&amp;` 而详情返回 `&` 的差异由该层统一处理，无需清缓存。

详情底部「加入收藏」先展开状态选择，可直接选择想看、在看、看过、搁置、抛弃；已有收藏可点击「修改收藏」。书籍 / 音乐 / 游戏使用对应的读 / 听 / 玩文案。看过、搁置和抛弃会进入评分与短评流程，保存或跳过后再提交对应状态；取消不修改收藏。想看与在看直接保存。

动态收藏文案按官方时间线类型显示具体动作（想看、在看、看过、搁置、抛弃及读 / 听 / 玩的对应状态），不使用当前收藏状态覆盖历史动态。卷数仅在书籍存在有效总数或已读卷数时显示；动画不显示卷数字段，未知章节 / 卷数总数不再显示 `??`。

- 发现：动画、书籍、游戏、音乐、三次元，支持排行 / 最新切换和分页。
- 首页分类栏滚动到顶部后吸顶，支持吸顶状态下横向滑动与切换分类，返回顶部后恢复原位，并避开手机状态栏安全区域。
- 每日放送：按周切换，显示 Bangumi 标注的放送作品。
- 旧版接口返回的 HTTP 封面地址在显示时统一转为 HTTPS，兼容 Android 图片加载；现有接口和收藏缓存无需清除。
- 搜索：中日文作品名、类型筛选、分页、空结果及失败重试。
- 详情：封面、简介、评分分布、作品资料、角色、章节。
- 评论标签页：短评、作者、评分、时间，长评标题和摘要，分页、刷新与失败重试；长评全文通过原站阅读。
- 底部「动态」页签：连接账号后查看自己与好友的收藏、章节进度、吐槽和日志，支持刷新、游标分页、点击作品进入详情，退出或切换账号时清除当前动态。
- 本机收藏：想看、在看、看过、搁置、抛弃；逐集记录进度，重启后保留。
- 账号同步：个人令牌授权、全量分页拉取收藏、收藏状态与逐集进度上传、离线修改重试。
- 评分与短评：手动标记看过或完成所有正篇章节后弹出评价表单，支持 1–10 分、清除评分、短评、跳过评价及后续修改。
- 章节「看到这里」：一键标记当前集及之前的正篇章节，按实际章节编号跨页补齐，保留后续已看记录，支持账号同步及离线重试。
- 本机片单与账号片单分别保存，支持手动导入，按账号隔离待同步修改。
- Android 返回键、状态栏安全区域、自定义图标和启动画面。
- 网络失败时可使用 15 分钟内的接口缓存；收藏独立持久化。

内容通过 [Bangumi 官方 API](https://bangumi.github.io/api/) 获取，Android 请求使用原生 HTTP。无后端服务、无内置 API 密钥。评论使用新站的匿名接口；好友动态使用新站的个人令牌授权接口，两者分别请求。长评全文、讨论、角色详情等完整社区内容通过系统浏览器打开 Bangumi 原站。

本版尚未实现社区发帖、视频播放、后台更新提醒和 OAuth 一键登录。账号连接使用 Bangumi 官方个人访问令牌。卸载或清除应用数据会删除本机缓存和未提交的修改，已经同步到账号的记录保留在 Bangumi。

## 连接账号与同步

v0.2.2 修复了详情页滚动时收藏操作栏悬在正文中的问题，操作栏始终固定在屏幕底部，并对齐居中的详情面板。此前的同步 404 修复继续保留：收藏读取使用 `/v0/me` 返回的 `username`，不再误用数字 UID。覆盖安装后，已连接的账号可直接点击「立即同步」，无需重新生成有效令牌。

1. 安装最新版 APK 后打开底部「收藏」。覆盖安装 v0.2.2 可保留旧版本的本机片单。
2. 点击「前往 Bangumi 获取个人令牌」，在 [官方令牌页面](https://next.bgm.tv/demo/access-token) 登录自己的 Bangumi 账号并生成个人访问令牌。
3. 回到 App，将令牌粘贴到「个人访问令牌」，点击「连接并同步」。无需在 App 中输入 Bangumi 密码，也不需要把令牌发给开发者或放入源码。
4. 连接后会拉取账号收藏；收藏状态和章节标记会自动提交。再次打开 App、恢复到前台、网络恢复时会同步，也可点击「立即同步」。App 处于前台时，未提交修改会每分钟重试。
5. 旧的本机片单不会自动上传。点击「导入本机片单」并确认后，新增收藏及已看章节会上传；已存在的云端收藏状态、评分、短评、标签和私密设置不会被导入覆盖。

账号修改只提交当前改动的状态字段或章节 ID，不用本机的整份记录覆盖账号。修改成功一部分、失败一部分时，仅未成功的部分保留待重试。全量片单拉取失败时保留原缓存。不同账号的片单和修改队列分别存储，退出账号后可继续使用原来的本机片单。

## 评分与短评

在详情「我的收藏」选择「看过」，或将全部正篇章节标记完成后，会打开评分与短评弹窗。已在 Bangumi 写过的内容会预填。可以「保存并标记看过」，也可以「暂不评价，标记看过」保留已有评价。点击关闭则不修改收藏状态；已经标记的章节仍会保留。章节是否全部完成按接口的全量章节总数判断，不会把当前一页或少于已知计划集数的放送中作品当作全部完成。

「我的收藏」中的「评分与短评」可随时修改已有评价，保持当前收藏状态。清除评分提交 `rate: 0`，清空短评提交空字符串。账号模式只提交 `rate` 和 `comment`，保留私密设置和标签；离线评价会保存在本机账号缓存中，联网后重试。未登录时评价保存在本机；手动导入新收藏时会一起上传，账号已有收藏的评价不会被本机导入覆盖。

Android 端令牌使用 Android Keystore 生成的 AES-GCM 密钥加密保存，关闭应用自动备份及 Capacitor 调试日志。网页预览令牌仅保存在内存，刷新后需要重新连接。令牌过期或缺少写入权限时会提示更新授权，未提交修改仍会保留。

当前公开 v0 收藏接口没有提供删除条目收藏的操作，因此账号片单的删除通过「在 Bangumi 管理收藏」进入原站操作，再点击「立即同步」刷新。新收藏使用 Bangumi 接口默认的可见性；已有收藏的私密设置保持原样。

此版本未配置 OAuth 应用或授权交换后端。官方 OAuth 流程需要注册应用及 `client_secret`，不能将服务端密钥直接内置到 APK；个人令牌方式可直接使用，无需部署额外服务。[官方认证文档](https://github.com/bangumi/api/blob/master/docs-raw/How-to-Auth.md)

官方开放接口没有提供账号密码授权方式。要免去手动复制令牌，可接入官方 OAuth：在官方网页用账号密码登录并授权，再回到 App。该方式需要注册 Bangumi 应用、配置回调地址及授权交换服务；当前 APK 尚未具备这些配置。

## 运行与构建

动态表情沿用原站图片与编号，支持吐槽以及带短评的单条收藏动态（非批量收藏），分别调用 `/p1/timeline/{id}/like` 和 `/p1/subjects/-/collects/{collectID}/like`。支持添加、更换与取消，服务端确认后才更新已选状态和人数；每种表情显示人数，总人数按用户 ID 去重，可展开查看互动者，刷新动态时重新读取原站数据。章节进度、日志等未提供表情接口的动态不显示发表情按钮。

好友动态先用 `/p1/friendlist` 验证授权并获取好友 ID，再读取 `/p1/timeline?mode=friends`，按好友和当前账号 ID 筛选返回记录；没有好友时读取自己的时间线，避免接口回退为全站动态。该接口匿名请求可能回退为全站动态，所以不会在未连接账号时读取。动态不进入公共缓存，也不持久化到本机。页面重试会重新获取好友列表。官方接口可能变化，授权受限时可更新个人令牌或到原站查看。

评论使用 [官方新站接口](https://bangumi.github.io/dev-docs/) 的 `/p1/subjects/{id}/comments` 和 `/reviews`，属于可能变化的接口；变化或访问受限时可从评论页进入原站。Android 直接访问新站；Vite 开发 / 预览通过同源代理访问，Windows 自动读取系统网络代理，其他平台可通过 `BANGUMI_HTTP_PROXY` 配置开发网络代理。

```powershell
cd D:\Projects\Website-Apps\bangumi
npm ci
npm run dev
```

浏览器预览地址为 `http://localhost:5173`。开发服务使用局域网监听，可通过电脑 IP 在同一网络的手机浏览器预览。

编译 Android 需要 JDK 21、Android SDK Platform 36 和 Build Tools 35 / 36。本机工具链已配置在 `.toolchain/`，不改变全局 Java 配置。

```powershell
# 新环境首次配置（下载官方 JDK 和 Android SDK）
powershell -ExecutionPolicy Bypass -File scripts/setup-android.ps1

# 编译并复制 APK
npm run android:build
```

输出位置：`artifacts/bangumi-pocket-debug.apk`。当前安装包使用开发调试签名，GitHub Release 保留同一签名以支持覆盖升级。最低 Android 7.0，建议使用更新的 Android System WebView。

### 发布到 GitHub Release

每次发布前更新前端和 Android 版本、`CHANGELOG.md` 对应版本条目，完成必要验证，提交源码并推送到 `origin/main`。安装并登录官方 GitHub CLI 后运行：

```powershell
npm run android:release
```

该命令构建 APK，核对版本、包名和签名，生成 SHA256 校验文件和供 App 检查更新的 update.json 附件，将版本日志作为 Release 说明。附件先上传至草稿，核实后再公开发布，最终输出下载链接。已发布的版本不会覆盖；修复后使用新版本号发布。保留现有签名密钥，不要随意更换，以保证用户可以覆盖升级。

已有通过验证的本机安装包可跳过重新构建：

```powershell
npm run android:release -- -ExistingApk artifacts/bangumi-pocket-0.9.2-debug.apk
```

仅本地校验安装包、生成说明和校验文件，不发布：

```powershell
npm run android:release -- -ExistingApk artifacts/bangumi-pocket-0.9.2-debug.apk -ValidateOnly
```

也可以用 Android Studio 打开 `android/` 工程。前端修改后需执行 `npm run android:sync` 再编译 Android。

## 验证

先启动 `npm run dev`，再执行：

```powershell
npm test
npm run test:sync
npm run test:text
node scripts/test-account-ui.mjs
node scripts/test-comments.mjs
node scripts/test-friends.mjs
node scripts/smoke-live.mjs
```

UI 测试默认使用已安装的 Chrome，测试收藏持久化、章节记录、搜索、放送切换、断网和响应式宽度。接口响应使用记录的真实作品 / 日历数据，章节使用测试数据，避免接口变化干扰功能验证。`smoke-live.mjs` 直接验证实时 API 和封面加载。

同步单元测试覆盖分页、账号隔离、重启后离线队列、部分成功重试、全量拉取失败保留缓存、导入合并及授权失效。账号端到端测试使用模拟账号响应，验证真实请求格式、空响应 204、选择性章节更新、断网恢复及令牌不进入浏览器持久化存储。

测试截图保存于 `artifacts/`。测试没有使用真实个人令牌对生产账号执行写入；真实账号授权、私密收藏与 Android Keystore 持久化仍需安装 APK 实测。

动态测试使用模拟账号，覆盖自己与好友 ID 筛选、无好友时自己的动态、官方表情图片加载、互动添加 / 更换 / 取消及人数、提交失败、分页、授权错误、退出隔离和五页签窄屏布局。已核对官方服务端与前端源码以及线上接口的匿名回退和无效令牌行为；有效令牌下的真实账号动态和表情写入仍需安装验证。

## 目录

`src/App.tsx` 为页面与交互，`src/api.ts` 为内容接口，`src/account-api.ts` 为认证和账号接口，`src/sync.ts` 为账号同步与队列，`src/AccountPanel.tsx` 为授权界面，`src/vault.ts` 与 Android `AccountVaultPlugin.java` 为凭据保存，`src/styles.css` 为手机布局，`android/` 为原生工程，`scripts/` 为构建和测试脚本。

接口参考： [Bangumi API 源码与说明](https://github.com/bangumi/api)。搜索接口属于实验性接口，未来接口变化可能需要调整客户端。
